# AI 러닝크루

부산 동구 AI 러닝크루의 프롬프트 챌린지를 운영하는 모바일 우선 웹앱입니다. 참가자는 본인 이름을 선택한 뒤 크루 전체의 진행 상황을 먼저 확인하고, AI 활용 링크 공유와 개인 실천 기록을 이어갈 수 있습니다. 운영진은 참가자·면제·미제출 판정과 월별 정산을 관리합니다.

- 운영 사이트: <https://prompt-homework-aicrew.antae98.workers.dev>
- 관리자 화면: <https://prompt-homework-aicrew.antae98.workers.dev/admin>

## 최근 반영 사항 · 2026-09-16

- **이름 선택 후 메인 화면** 최상단에 크루 전체 대시보드를 배치했습니다. 이름을 고르는 첫 화면과는 구분됩니다.
- 크루 공동 목표, 확정 기준 제출률, 오늘 완료·대기 인원과 전체 활동 그래프를 표시합니다. 개인 기록과 알림 설정은 그 아래에 배치하며, 알림 설정은 마지막 카드입니다.
- 메인과 성장 상세가 같은 집계 결과와 화면 컴포넌트를 사용합니다. 개인 달력의 조회 월을 바꿔도 크루 전체 기간 누적 수치는 유지됩니다.
- 활동 그래프와 크루 공유 합계에서 마감 후·주말·공휴일·운영 제외일의 공유를 제외합니다. 원본 공유 피드는 유지합니다.
- 기존 `share` 링크 외에 `/notebook/`이 포함된 HTTP(S) 링크도 등록·수정할 수 있습니다.

## 참가자 화면 안내

1. 기수 탭에서 본인 이름을 선택합니다. 선택한 이름은 현재 기기에 기억됩니다.
2. **내 현황**에서 전체 챌린지 진행 상황 → 개인 오늘 상태·실천 기록·월별 달력 → 알림 설정 순서로 확인합니다. 종료 기수 참가자에게는 숙제 대신 자율 공유 안내를 표시합니다.
3. **등록**에서 공유방법을 확인한 뒤 링크와 수정·삭제용 비밀번호를 입력합니다. 제목과 설명은 선택 사항입니다.
4. **공유**에서 크루의 활용 사례를 탐색하고, **성장**에서 전체 크루 현황과 본인의 월별 성장 기록을 확인합니다.

### 대시보드 집계 기준

| 항목 | 기준 |
| --- | --- |
| 기간 경과 | 챌린지 시작일~종료일의 달력상 경과 비율. 제출률과는 별개 |
| 확정 기준 제출률 | 현재 챌린지 참가자 전체의 완료 횟수 ÷ (완료 + 확정 미제출 횟수). 오늘 대기·면제·휴일·비대상일 제외, 확정 기록이 없으면 ‘집계 전’ |
| 오늘의 크루 현황 | 오늘 제출 대상 = 완료 + 대기 + 마감 후 미제출 인원. 면제·휴일·참여 기간 밖은 제외 |
| 크루 활동·공유 합계 | 현재 챌린지 전체 기간 중 오늘까지의 링크. 마감 후(23:01부터)·주말·공휴일·운영 제외일·종료 기수 자율 공유 제외 |
| 활동 그래프 | 일별 격자·주별 막대·누적 그래프. 날짜 선택 시 공유 링크 수와 공유한 인원 표시. 같은 날 여러 번 공유한 참가자는 인원 집계에서 한 명으로 계산 |
| 개인 기록·공유 피드 | 개인 월별 기록과 원본 공유 피드는 별도 유지하므로 크루 집계 대상 링크 수와 다를 수 있음 |

확정 기준 제출률이 100%여도 **오늘 모두 완료했다는 뜻은 아닙니다.** 오늘 완료·대기 인원을 함께 확인하세요. 크루 대시보드는 누구의 이름을 선택해도 같은 전체 합계를 보여주며, 다른 참가자의 개인별 미제출이나 순위는 나열하지 않습니다.

## 주요 기능

### 매일 실천과 알림

- 매일 AI를 한 번 써보도록 돕는 선택형 3분 미션과 시작 프롬프트 복사
- 운영진의 날짜별 미션 예약, 미등록 날짜의 기본 미션 자동 제공
- 이번 주 실천 기록, 미제출 뒤 다시 시작 안내, 링크 우선 제출과 완료 확인
- 기기별 선택형 웹 푸시 알림(08:00~22:59 KST, 1분 단위 설정, 최대 약 1분 후 발송)
- 제출 완료·휴일·면제·참여 기간 밖에는 알림 제외, 기기에서 언제든 해제
- 관리자 전용 오늘 미제출 필터·안내문 복사·연속 미제출 안부 확인·주간 실천 집계
- 순위 대신 따라 해보기 쉬운 사례 추천. 실천 수치는 제출 기록 기준이며 실제 AI 사용을 자동 측정하지 않음

### 참가와 링크 공유

- 로그인 없는 참가자 이름 선택과 기기별 선택 기억
- 참가자 명단의 기수 탭: 활성 2기 기본 표시, 1기 탭에서 이름을 선택해 자율 공유
- 종료 기수의 공유는 원래 기수에 저장되며 공통 피드에 표시. 숙제 의무·미등록 차감·알림 대상에서 제외
- 이름 아래 소속 표시. 소속은 초기 공란이며 관리자 → 참가자 관리 → 수정에서 기수별로 입력
- URL·선택 제목·선택 설명·수정/삭제 비밀번호를 포함한 제출
- HTTP(S) 주소 전체에 `share` 또는 `/notebook/`이 포함되면 등록·수정 가능(대소문자 구분 없음)
- 한국 시간 기준 `23:00:59` 제출 인정, `23:01:00` 미제출 확정
- 제출 당일 숙제 제출 마감 시각(`23:00`)까지 참가자 수정·삭제
- 주말·대한민국 공휴일·운영 제외일·개인 면제일 처리
- 공유 피드, 날짜 탐색, 검색, 추천 프롬프트, 기기별 북마크
- 비교 없는 개인 성장 기록, 크루 공동 목표, 전체 링크 수와 연속 달성

링크 검사는 주소 전체에 `share` 또는 `/notebook/`이 포함되는지 확인합니다. 외부 서비스의 실제 공개 권한까지 검사하지 않으므로, 등록 전에 다른 사람도 열 수 있는 공유 링크인지 확인해주세요.

### 관리자 운영

- 관리자 인증, 운영자 선택, 다기수·참가자·공지·제출물 관리
- 날짜별 벌금 단가, 실제 납부액, 예상 환급액, CSV/XLSX 정산
- 모든 주요 관리자 변경의 감사 기록

## 기술 구성

- Next.js 16 App Router · React 19 · TypeScript · Tailwind CSS
- 운영 실행 환경: Cloudflare Workers + vinext
- 데이터 저장: Supabase PostgreSQL. 브라우저는 DB에 직접 접근하지 않고 서버 API를 사용
- 비밀번호 해시·검증: Supabase `password-crypto` Edge Function
- 테스트: Vitest · ESLint · TypeScript 검사, Next.js/Cloudflare 빌드 및 브라우저 확인

## 로컬 실행

```bash
npm ci
npm run dev
```

Supabase 없이 실행하면 개발 환경에서 자동으로 체험 데이터가 표시됩니다. 참가자 화면은 `http://localhost:3000`, 관리자 화면은 `http://localhost:3000/admin`입니다. 로컬 체험 모드의 초기 관리자 비밀번호는 `010723`입니다.

실제 DB를 사용하려면 `.env.example`을 참고해 `.env.local`을 만들고 `DEMO_MODE=false`로 설정하세요. 비밀값에는 절대로 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.

## 필수 환경변수

| 이름 | 설명 |
| --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_SECRET_KEY` | 서버 전용 Supabase Secret Key |
| `ADMIN_PASSWORD_PBKDF2` | Cloudflare 운영용 PBKDF2 관리자 비밀번호 검증값 |
| `ADMIN_PASSWORD_HASH` | 이전 bcrypt 검증값과의 호환용 |
| `ADMIN_PASSWORD` | 로컬 개발에서만 사용하는 대체 관리자 비밀번호 |
| `ADMIN_SESSION_SECRET` | 32자 이상의 임의 문자열 |
| `DEMO_MODE` | 운영 환경에서는 반드시 `false` |
| `VAPID_PUBLIC_KEY` | 웹 푸시 구독용 P-256 공개키(base64url) |
| `VAPID_PRIVATE_JWK` | 웹 푸시 발송용 P-256 비밀키(JWK JSON), Workers Secret에만 저장 |

운영 환경에서는 `ADMIN_PASSWORD_PBKDF2`를 사용합니다. 비밀값은 Git에 커밋하지 않고 Cloudflare Workers Secret으로만 관리합니다.

## 데이터베이스

마이그레이션과 개발용 초기 데이터는 `supabase/` 아래에 있습니다.

```bash
npx supabase start
npx supabase db reset
npx supabase test db
```

브라우저 역할은 DB 테이블 권한이 없고, 앱의 서버 API만 Secret Key로 접근합니다. RLS와 권한 회귀 검사는 `supabase/tests/database/security.test.sql`에 있습니다.

## 검증

아래 명령을 순서대로 실행합니다.

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run deploy:dry-run
```

Next.js와 vinext 빌드는 생성 타입 경로를 공유하므로 동시에 실행하지 않습니다. `deploy:dry-run`은 Cloudflare용 빌드와 배포 사전 검증을 수행하며 운영 사이트에는 반영하지 않습니다.

2026-09-16 기능 배포 시 자동 테스트 **124개**, 린트, Next.js 빌드, Cloudflare 배포 사전 검증이 통과했습니다. 배포 후에는 운영 사이트에서 이름 선택 → 전체 현황 → 성장 상세 동선, 집계 일치, 모바일 배치와 알림 카드 위치를 확인했습니다. 실제 운영 DB에는 검증용 게시물을 등록하지 않았습니다.

Cloudflare Workers 배포 순서와 운영 전 점검은 [운영 및 배포 안내](docs/OPERATIONS.md)를 확인하세요. 설계 근거는 [아키텍처 문서](docs/ARCHITECTURE.md)에 정리되어 있습니다.

## 여러 PC에서 작업하기

GitHub의 `main` 브랜치를 두 PC 사이의 기준으로 사용합니다.

1. 작업을 시작하기 전에 `git pull`로 최신 내용을 받습니다.
2. Codex 앱에서 이 저장소 폴더를 로컬 프로젝트로 엽니다.
3. 수정 후 타입 검사, 린트, 테스트와 Cloudflare 빌드를 실행합니다.
4. 작업이 끝나면 변경 내용을 커밋하고 `git push`합니다.
5. 다른 PC에서는 다시 `git pull`한 뒤 작업합니다.

두 PC에서 같은 파일을 동시에 수정하지 않습니다. `.env*`, `.dev.vars*`, Supabase Secret Key, 관리자 비밀번호와 Cloudflare 인증 정보는 절대로 커밋하지 않습니다.
